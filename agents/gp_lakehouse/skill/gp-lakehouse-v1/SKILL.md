Один агент, без сабагентов. Выполняй только нужный режим, не обследуй весь стенд. Артефакты текущей цепочки формирует скрипт, а не свободная генерация модели.

1. Для текущей цепочки выполни один раз `python scripts/build.py --output <папка_текущей_сессии>/migration --mode all`. Путь к scripts относительно этой skill-папки. Это проверит source SHA-256, сформирует все 20 DDL, полный all_ddl.sql, 20 Spark-преобразований с DQ, runtime и один DAG. Нужен только DDL — `--mode ddl`; только логика/DAG — `--mode logic`.
2. В ответе дай ссылки на `all_ddl.sql`, `migration-code.zip`, `dag/oil_production_spark_candidate.py`, `DIFF.md` и `result.json` из реально созданной папки. Для полного DDL выдавай файл, не двадцать сокращённых примеров. Не меняй сгенерированный код и не пересчитывай числа моделью.
3. Если пользователь прислал другое DDL, сохрани его без изменения и вызови `python scripts/translate_ddl.py input.sql --output ddl.sql`. Скрипт поддерживает CREATE TABLE с явными колонками; произвольный VIEW требует исходных типов/контракта. При отказе передай причину, не угадывай типы.
4. Для разбора прочитай DIFF.md и только нужный source-файл. В текущем профиле oil_gp_release → apply_batch/refresh_production заменены Spark MERGE/SCD2/Kimball; refresh_downtime второй цепочки остаётся в GP. Raw уже должен поступать, INITIAL должен быть принят перед исполнением release. Это предусловия будущего запуска, не действия этого навыка.
5. Для новой/изменённой бизнес-логики нужен новый проверенный профиль: изменившийся source SHA блокирует повторное использование старого перевода. Не называй шаблон универсальным компилятором PL/pgSQL. Объясни неподдержанный объект и запроси точный код/тип.
6. Публикация только если пользователь явно попросил зарегистрировать DAG. Сначала `dp103-airflow.list_dags(only_active=false, dag_id_pattern="oil_production_spark_candidate")`: приостановленный DAG тоже должен быть виден. Не вызывай get_dag для отсутствующего ID (404 может завершить run ошибкой). Публикуй через `publish_reviewed_dag(artifact_id="oil-production-1.1")`: сервер проверяет SHA-256 и читает точный reviewed source, Python-код в аргументы модели не передаётся. Не используй generic publish_dag для этого профиля. DAG ID oil_production_spark_candidate, cron */1 * * * *, одна task, pool oil_dlh_writer, paused. После публикации проверь list_dags: get_dag вызывается только когда ID появился. Если синхронизация ещё идёт, верни PUBLISHED_WAITING_IMPORT и ссылку; не публикуй снова. Если ID уже есть — сравни code SHA с hash в fileloc; идентичный код не публикуй повторно. При иной версии остановись и покажи diff. Не перезаписывай oil_gp_release или oil_dlh_release.
7. Никогда не вызывай trigger/unpause, не выполняй DDL/DML и Spark jobs. Если get_dag показал paused=false, вызови pause_dag и проверь снова. Регистрация успешна только при наличии DAG, paused=true, без import errors; без доступного MCP статус PREPARED, а не REGISTERED.

Максимум: один build, один повтор чтения статуса публикации за обращение; при ошибке не запускай бесконечный цикл. Финал короткий: что создано, сколько объектов, SHA-256, файлы, PREPARED/REGISTERED_PAUSED и ограничения. Одинаковые mode и исходный профиль должны возвращать одинаковые байты и hashes; время, случайные IDs и run_id в код не добавляй. temperature=0 не доказывает детерминизм модели: проверяем именно артефакты.
