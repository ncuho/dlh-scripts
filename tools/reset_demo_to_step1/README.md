# Сброс первой цепочки к шагу 1

Утилита для повторения ручного переноса «Добычи по месторождениям» на текущем стенде. Запускается на Mac после завершения показа. Пароли и JWT в командную строку не передаются: используются существующие SSH-маршруты и подключения Platform Bridge. Нужны VPN, SSH-доступ и `platform-bridge/.venv` рядом с каталогом `webinar-delivery-2026-11-20`.

## Запуск

Из этой папки сначала посмотрите состав очистки:

```bash
./reset-demo.sh --dry-run
```

Без аргументов тоже выполняется только просмотр. Для реального сброса:

```bash
./reset-demo.sh --apply
```

В конце ожидается `"status": "READY_FOR_STEP_1"`. Для отдельной проверки без изменения сервисов:

```bash
./reset-demo.sh --check
```

Скрипт не открывает дополнительное интерактивное подтверждение после явного `--apply`. `--dry-run` ничего не останавливает и не удаляет.

## Что происходит

1. Читает фактические ресурсы, проверяет принадлежность и сохраняет определения в приватный локальный журнал. Находит **новые Superset IDs** по binding dataset к `dlh.bronze/silver/gold`, а не по ID предыдущего показа.
2. Ставит `oil_layered_migration`, `oil_dlh_catchup`, `oil_dlh_release` на паузу. Старый `oil_source_snapshot`, если установлен, тоже оставляет на паузе.

   Если зарегистрирован агентский `oil_production_spark_candidate`, он тоже входит в проверку активных writers и остаётся на паузе. Его отсутствие не мешает сбросу; установленный код DAG сохраняется.
3. Посылает SIGINT генератору `live_oil_updates.py`, дожидается завершения доставки текущего события и сохраняет `/tmp/oil-live-production.json`.
4. Ждёт завершения активных целевых DAG. По умолчанию — до 1800 секунд; текущий Spark job принудительно не убивается. `--wait-seconds 600` меняет предел ожидания. По таймауту удаление целевых объектов не начинается, но расписания и генератор уже могут быть остановлены.
5. Удаляет `manual-oil-production-a`, только его consumer groups и control topic `manual-oil-production-a-control`.
6. Удаляет целевые Superset dashboard/charts/datasets и их карточки Catalog. Если dashboard содержит посторонние графики или целевой chart используется исходным dashboard 3/4, останавливается до очистки.
7. Удаляет известные таблицы `bronze/silver/gold` через LakeKeeper с `purgeRequested=true`, затем namespaces. Сверяет сохранённые UUID, не удаляет произвольные S3-префиксы. Физическая очистка S3 выполняется LakeKeeper асинхронно.
8. Переносит активные receipts INITIAL/catchup/release в архив Airflow worker и прежние паспорта с Desktop в локальный журнал. Историю DAG runs и task logs сохраняет.
9. Проверяет отсутствие целевых объектов, доступность исходных отчётов 3/4 и GP-данных, работу исходного Kafka sink, состояния DAG и отсутствие ошибок импорта.

После сброса создавайте таблицы и новый отчёт с первого шага инструкции. Все три целевых DAG остаются установленными и на паузе. CIAM-роли и warehouse `dlh` сохраняются, но новые таблицы получают новые UUID, поэтому grants проверяются заново. Возобновление генератора на Kafka VM:

```bash
sudo -u kafka env PYTHONPATH=/opt/kafka-demo/generator/site python3 /opt/kafka-demo/oil-generator/live_oil_updates.py --interval 10 --resume
```

## Продолжение после сбоя

В начале `--apply` выводит строку `Журнал: /…/platform-bridge/var/demo-resets/<id>`. Если команда оборвалась, сначала прочитайте ошибку, затем продолжайте **тот же** журнал:

```bash
./reset-demo.sh --resume '/полный/путь/из/строки/Журнал'
```

Исходные IDs/UUID остаются в журнале; завершённые фазы повторно не выполняются, частично завершённая фаза проверяет текущее состояние. Ответ 404 для уже удалённого объекта допускается. Чужой или пересозданный объект с другим UUID вызывает остановку. После COMPLETE повторный `--resume` только проверяет состояние.

Последний путь хранится в `platform-bridge/var/demo-resets/latest.json`. Журнал `journal.json` содержит план, выполненные фазы и итоговый отчёт; права файла 0600. Это резервная копия определений/паспортов, **не** резервная копия всех данных Iceberg. Сброс удаляет мигрированную копию, восстановление из журнала не предусмотрено — следующий проход загружает новую.

При `blocked.json`, незавершённом write intent или неизвестном исходе Spark-команды скрипт прекращает очистку до разбора результата. Не исправляйте это удалением receipt вручную. Во время сброса не запускайте UI/CLI writers и не пересоздавайте целевые таблицы.

## Граница сброса

GP-таблицы, функции, обе исходные цепочки, dashboard 3/4, topic `oil.events.v1`, исходный consumer и его offsets сохраняются. Сохраняются код GitHub, connections, учётные данные, сервисы, роли и история Airflow. Исходный `oil_gp_release` остаётся включённым.

Это возврат **состояния миграции** к шагу 1. Накопленные исходные события и GP-история не обнуляются, поэтому старые числовые baseline и IDs не переиспользуйте. Пространства других проектов, включая `pb_*` Platform Bridge, и вторая цепочка не очищаются этой утилитой. Посторонние объекты внутри трёх выбранных namespaces блокируют сброс.

`reset_demo_to_step1.py` содержит комментированные операции сервисов и порядок фаз; `reset-demo.sh` только выбирает существующий Python environment. Журналы и метаданные исполнения в GitHub не публикуются.
