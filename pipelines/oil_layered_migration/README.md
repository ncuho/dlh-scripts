# Перенос добычи с прямым чтением Greenplum

`oil_layered_runtime.py` исполняет INITIAL/REFRESH, `oil_layered_plan.py` задаёт 20 объектов и зависимости, SQL лежит в `production_online/<symbol>`, отдельные проверки — в `checks/`. `oil_source_lock.py` проверяет стандартные блокировки исходной транзакции. `oil_layered_cedrus.py` использует существующую авторизацию Cedrus MCP.

Источник `oil_stg` отображается в Bronze (6 объектов), `oil_dds` — Silver (9), `oil_mart` — Gold (5). Независимый Kafka sink пишет седьмую Bronze-таблицу `__raw_events`. INITIAL сохраняет исходные имена; REFRESH строит отдельные `_next`.

Перед каждой границей оператор приостанавливает GP sink и source DAG, завершает READY-партии и открывает административную транзакцию SHARE-lock. Cedrus читает исходные таблицы напрямую. Служебная схема и копии источника не участвуют. Пока идут загрузка и сверки, Kafka/raw принимают новые сообщения, а исходный GP остаётся доступным для чтения на последнем рассчитанном состоянии.

Конфигурация Trigger DAG содержит `mode` и `source_lock` с PID, database_oid и virtualtransaction из psql. Runtime проверяет действительные locks до/после операций и перед READY. PID без идентификатора транзакции недостаточен. При потере окна новый выпуск не принимается. После READY и ручных сверок оператор COMMIT/ROLLBACK снимает locks и возобновляет GP connector и source DAG; SQL target записан отдельными операциями и этим COMMIT не управляется.

Airflow задаёт порядок, SQL/Spark вычисляют ключи, версии и SCD2. INITIAL включает 14 Cedrus / 6 Spark операций и 60 проверок; REFRESH — 5 Cedrus / 15 Spark и 53 проверки. REFRESH закрепляет snapshots INITIAL/raw, читает полное окно C0–C1 с перекрытием по умолчанию 10 offsets перед C0, исключает повторы координат и event_id. Конфликт payload блокирует выпуск. SQL MERGE в принятые таблицы не выполняется.

Каждая запись журналируется до исполнения; snapshot, реальный SQL и DQ сохраняются в `/opt/airflow/logs/oil_layered_migration/`. Подтверждённые записи неуспешного кандидата компенсируются в обратном порядке. Raw, источник и принятый INITIAL не очищаются. UNKNOWN_OUTCOME или чужой snapshot/location ведут в MANUAL_RECONCILE без слепого удаления. Компенсация не делает run успешным.

После освобождения исходных locks live GP уже может быть впереди. Source-зависимые проверки receipts можно повторять только в соответствующем удерживаемом окне; для дальнейшего аудита сохраняют их фактические результаты и target snapshots. Публикация Superset — отдельная проверка после READY. Код и регистрация Catalog не означают уже выполненный перенос.
