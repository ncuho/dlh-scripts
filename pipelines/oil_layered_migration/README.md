# Прямая миграция нефтедобычи

`oil_layered_migration` выполняет INITIAL или REFRESH одной task `migrate_and_validate`: одно native GP-подключение сохраняет REPEATABLE READ READ ONLY для всех двадцати объектов. Таблица транспортного экспорта не создаётся. Конфигурация: `{"mode":"initial"}` либо `{"mode":"refresh","overlap_offsets":10}`.

`oil_gp_snapshot.py` выбирает применённый непрерывный префикс без ожидания пустой очереди. `oil_direct_source.py` пишет типизированные строки сразу в нужные Iceberg-таблицы и сверяет полные мультимножества строк по SHA-256. `oil_layered_runtime.py` задаёт порядок, проверки, receipts и компенсацию. `oil_layered_plan.py` содержит зависимости и 65 INITIAL / 58 REFRESH gates. SQL каждого объекта лежит в `production_online`. `oil_layered_spark.py` запускает отдельные Spark Connect sessions под управлением DAG.

INITIAL: 14 прямых копирований через Python/Cedrus и 6 Spark-расчётов. REFRESH: 5 Cedrus и 15 Spark шагов, pinned INITIAL + полный raw-диапазон C0–C1 с перекрытием. Родитель должен получить VALIDATED до дочернего INSERT. Проверяются PK, NULL, FK, SCD2, точные значения и наличие всей дельты. READY закрывает исходную транзакцию и разрешает отдельную приёмку отчёта; DAG сам не переключает Superset.

Source batch_id сохраняются в INITIAL. Новые Lakehouse доставки используют отдельные отрицательные batch_id из partition/offset; сначала создаётся их batch_control, затем Stage/DDS. Оригинальные sink batch_id остаются в raw. Бизнес-ключи не меняются. Исходные GP batch_id должны быть положительными; границы партиций/offsets проверяются до записи.

При отказе подтверждённые кандидатные записи компенсируются в обратном порядке. Неизвестный исход или чужой snapshot блокирует автоматическое удаление. Принятый INITIAL и raw при REFRESH не очищаются. Iceberg не предоставляет общей транзакции всех таблиц: кандидат не публикуется до READY, а прямые сторонние записи в его таблицы во время run запрещены операционным контрактом.

Receipts содержат SQL повторных сверок, исходные подписи и pinned target versions. Они не содержат копии исходных строк. Потерянную GP-транзакцию нельзя заменить новым подключением внутри того же run. Исторические альтернативы source_lock/fence не используются.
