# Online-перенос производственной отчётности

Полный 20-объектный контракт первой бизнес-цепочки: Stage, история Data Vault и звезда отчёта добычи. В каждой папке лежат DDL, INITIAL, REFRESH, phase-aware проверки и назначение объекта. Это код бизнес-сущностей; execution receipts, snapshots, tokens и результаты запусков в Git не входят.

INITIAL читает committed GP capture C0 через Cedrus и строит производные проекции Spark. REFRESH использует неизменный INITIAL и весь bounded raw диапазон C0–C1; новый release не меняет уже опубликованные таблицы. Все source-ссылки при выполнении сверок направляются на физический C0/C1 capture, а не живой GP. Служебный архив исходных batch/checkpoint/coalesce сохраняется как аудит INITIAL, а не имитирует состояние нового sink.

Placeholders `{{source:symbol}}`, `{{target:symbol}}`, `{{initial:symbol}}`, `{{delta}}`, `{{cut_time}}` раскрывает проверенный runtime из согласованного manifest. Не запускайте шаблоны без раскрытия. Для checks исполняется только нужная phase: initial/refresh/both. Trino/Cedrus выполняет DDL и проверки; метка dialect в README определяет engine расчёта.

Набор SQL соответствует принятому переводу первой цепочки. Это не встроенный в универсальный Bridge рецепт: новый проект заново обследует каталог, получает перевод и review. Вторая цепочка простоев не создаётся этим кодом, хотя её исходные события остаются в общем event ledger.
