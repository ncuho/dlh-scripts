# Подготовка выпуска расчёта

Этот код — проект, не проверенный на текущих версиях Spark Connect, Iceberg, LakeKeeper и правах. Для production необходимо проверить поддержку `VERSION AS OF`, CTAS `writeTo(...).using('iceberg').create()` и чтения metadata table `.snapshots` на целевой платформе. Перенос и расчёт в этом шаге не запускались.

Создайте JSON-манифест восьми снимков (числа ниже — только образец, не реальные snapshot ID):

```json
{"cut_id":"approved-cut-001","snapshots":{"sat_product":101,"sat_store":102,"sat_shipment":103,"sat_return":104,"hub_shipment":105,"hub_return":106,"link_shipment":107,"link_return":108}}
```

Названия строго соответствуют `dlh.commerce_vault.<name>`. Перед формированием манифеста нужно получить и зафиксировать совместимый срез всех входов; выбор любых восьми существующих снимков не доказывает логической согласованности. Убедиться, что snapshot retention удержит их до окончания выпуска и последующей сверки. Сохранять манифест неизменным в надёжном хранилище; SHA-256 исходных байтов включён в выходной манифест.

Запуск без записи: `python sales_job.py --input-manifest input.json --sample-rows 5`. Без `--input-manifest` dry-run читает текущие состояния и не гарантирует одинаковую границу на протяжении расчёта.

После отдельного согласования и установки внешнего single-writer fencing: `python sales_job.py --input-manifest input.json --stage-release demo_001 --release-manifest release.json`. Создаются пять новых Iceberg-таблиц в `dlh.commerce_dm` с именами `r_demo_001_dim_product`, `r_demo_001_dim_store`, `r_demo_001_fact_shipment`, `r_demo_001_fact_return`, `r_demo_001_sales_day`. Исходные и опубликованные таблицы не заменяются. Код проверяет gates бизнес-логики до записи, затем перечитывает число строк и snapshot ID каждой новой таблицы и создаёт **локальный** файл манифеста эксклюзивно после успешных проверок. Файл следует надёжно сохранить вместе с input manifest и логом; локальный путь не является общим registry и не механизм переключения BI.

Коммиты пяти Iceberg-таблиц независимы: при сбое могут остаться некоторые из них, а файл release.json отсутствовать. Создание с существующим именем завершится ошибкой; не переиспользуйте идентификатор, разберите частичный выпуск и удаляйте только после проверки владельца и ссылок. Возможна ошибка даже после создания таблицы и до записи её имени в журнале процесса: ищите все пять имён по release_id. Счётчики не доказывают содержимое или равенство с GP; необходимы сравнение схем, ключей, null, агрегатов и хешей по единой границе и бизнес-подтверждение. Манифест обозначает подготовку к проверке, а не переключение потребителей.

Внешний orchestrator должен обеспечить fencing, проверку отсутствия release_id и защита от посторонних изменений таблиц выпуска до/после сверки. Для атомарного переключения потребителей нужна отдельно спроектированная и проверенная точка активации, например единый транзакционный registry release_id, который умеют соблюдать все потребители. Одновременного атомарного изменения нескольких таблиц Iceberg этот скрипт не обеспечивает. CDC и доставка Kafka не входят в код.
